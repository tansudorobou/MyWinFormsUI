# 最終監査

## 実装と検証

| 要件 | 確認した証拠 |
| --- | --- |
| shadcn/ui相当の全項目 | 公式の64ページから一覧を取得。`components.json` / `docs/components.json` / `COMPONENTS.md` が全64項目と一致し、全ソースパスが存在 |
| 標準機能は再実装しない | 対応表の39項目は標準APIを直接使用。25項目は必要な動作だけをネイティブコントロールで合成。プリミティブの独自描画や外部UI依存なし |
| シンプルな実装 | ライブラリとサンプルの2プロジェクト。共通レイアウト、フィールド、ネイティブのイベントと選択・モーダル基盤を再利用 |
| デザインは後回し | Nativeが既定値。装飾の見た目やアニメーションを作り込まず、標準表示を使用 |
| デザインの一括差替 | `ThemeTemplate` と `ThemeSession`。JSON入出力、全体色/フォント/余白、ロール、動的追加、独立ポップアップへの継承と変更追従、標準復帰を操作検証 |
| 既存機能の保持 | 入力・登録・List<T>・DisplayName・キー/表示名・検索・ソート・列数自動調整・ルート16:9・スクロールの回帰検証 |
| 追加したUIの動作 | 開閉、前後/ループ、比率、検索/複数選択、スライダー、コマンド、通知の期限と非同期処理、添付、ページング、モデル検証、質問と再開、会話履歴/追従/仮想化等を実コントロールで検証 |
| 描画 | 7種類のチャート、7タブのギャラリー、狭い/広い実績画面をDrawToBitmapで出力。メッセージ本文が補助パネルに隠れる不具合を修正後、画像で再確認 |
| Release | `dotnet build WinformsUI.slnx -c Release` が警告0・エラー0。検証モードの28グループが成功 |
| ソースの利用 | `Export-Source.ps1` でTEMPの新規ディレクトリへ出力し、親のDirectory.Build.propsなしで単独Releaseビルドが成功 |
| パッケージの利用 | READMEと2つのテーマを含むNuGetパッケージを作成。TEMPの独立WinFormsアプリがローカルフィードから復元、ビルド、テーマ読込を実行して終了コード0 |

実行結果と画像: `artifacts/verification/`（生成物としてGit管理対象外）。
パッケージ: `artifacts/packages/WinformsUI.1.0.0.nupkg`（生成物としてGit管理対象外）。

UIライブラリの対象はコンポーネントの操作・データ・状態機能。Web固有のSSR/DOM/React/Tailwind環境や外部AI通信サービスはWindows FormsのUIとして移植しない。
アップロード・AI通信・DB検索・永続化はアプリ側の処理を受け取る。OSが描画する標準コントロールの外観は標準APIの範囲。

## GitHubと電源

対象は `origin` の `https://github.com/tansudorobou/MyWinFormsUI.git`、現在の `master` ブランチ。
実装・検証の後に通常のpushを行い、remote SHA = local HEADとクリーンな作業ツリーを確認する。
確認後に、強制終了オプションを付けず `shutdown.exe /s /t 0` を実行する。
リポジトリへのpush検証または電源操作が失敗した場合は、成功したと扱わない。
